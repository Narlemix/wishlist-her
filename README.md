# Вишлист

Список желаний со ссылками на магазины: https://narlemix.github.io/wishlist-her/

Сайт статический и живёт на GitHub Pages. Весь список хранится в `data.json`, страница просто показывает его. Это отдельная копия вишлиста https://narlemix.github.io/wishlist/: свой список, свои гости и брони, а вход владельца в одном браузере не путается с основным сайтом.

## Как редактировать

1. Владелец репозитория добавляет тебя в соавторы: Settings → Collaborators → Add people, ты принимаешь приглашение на почте или на https://github.com/notifications.
2. Создай классический токен на https://github.com/settings/tokens/new:
   - **Note** — например, «вишлист»;
   - **Expiration** — какой удобно (по истечении просто создай новый);
   - **Select scopes** → отметь только **public_repo**.

   Обычный fine-grained токен здесь не подойдёт: он видит только твои собственные репозитории, а этот принадлежит Narlemix.
3. Открой сайт, внизу нажми «Кабинет владельца» и вставь токен. Он хранится только в этом браузере.
4. Добавляй, меняй и отмечай подарки. Каждое изменение сохраняется коммитом в `data.json`, у остальных сайт обновится примерно через минуту.

## Быстрое добавление

После входа внизу сайта появляется кнопка «＋ В вишлист». Её нужно перетащить на панель закладок браузера. На странице товара в любом магазине нажми закладку: она прочитает название и цену прямо со страницы и откроет сайт с заполненной формой.

Для ссылок Wildberries сайт сразу подставляет название товара из его карточки. Цену WB он тоже пробует получить через открытый API магазина, но этот API часто отказывает, тогда цену подставит ежедневная проверка.

Ozon, Яндекс Маркет, AliExpress и другие магазины не дают сайту читать свои страницы, поэтому по вставленной ссылке у них ничего не подтягивается. Это не страшно: достаточно добавить одну ссылку, название можно не писать. До проверки товар показывается как «Товар с Ozon», а вечером проверка подставит название и цены.

С телефона на Android: открой сайт в Chrome или Яндекс Браузере, в меню выбери «Добавить на главный экран» / «Установить приложение». После этого в приложении магазина нажми «Поделиться» → «Вишлист» — откроется форма со ссылкой и названием. На iPhone то же делает быстрая команда, которая открывает `https://narlemix.github.io/wishlist-her/?add=1&url=<ссылка>`.

У товара хранятся две цены: `price` — со скидкой (что реально заплатить) и `priceOld` — без скидки (зачёркнутая).

## Гости и брони

Гости регистрируются по имени и паролю и бронируют подарки кнопкой «Подарю я». Один товар может забронировать только один человек, у товара появляется плашка «Хочет подарить <имя>». Имена уникальны без учёта регистра.

Аккаунты и брони хранятся в отдельном проекте Firebase (бесплатный тариф Spark), не в том же, что у основного вишлиста:

- `firebase-config.js` — настройки веб-приложения Firebase (они публичные по задумке Firebase);
- `firestore.rules` — правила базы: брони может создавать только вошедший гость от своего имени, удалять — только свою, менять чужие нельзя.

Пока в `firebase-config.js` стоит `null`, гостевые функции скрыты, а список просто показывается.

### Как подключить Firebase

1. На https://console.firebase.google.com нажми «Создать проект», Google Analytics можно выключить.
2. Build → **Authentication** → Get started → Sign-in method → **Email/Password** → включить (только первый переключатель).
3. Там же Settings → **Authorized domains** → Add domain → `narlemix.github.io`.
4. Build → **Firestore Database** → Create database → регион `eur3 (europe-west)` → production mode. На вкладке **Rules** замени всё содержимым `firestore.rules` и нажми Publish.
5. Project settings (шестерёнка) → Your apps → значок `</>` → зарегистрируй приложение (Hosting не нужен) и скопируй объект `firebaseConfig`.
6. Вставь его в `firebase-config.js` вместо `null`: `window.WISHLIST_FIREBASE = { ... };`.

Владелец может снимать любые брони. Для этого он регистрируется на сайте как гость, а в Firestore создаётся документ `admins/<имя в нижнем регистре>` (Firestore Database → Start collection → `admins` → Document ID = имя, поле любое). Записывать в `admins` можно только из консоли Firebase.

## Важность

У каждого желания один из пяти уровней, от самого важного к наименее: «Очень нужно», «Нужно», «Хочу», «Было бы приятно», «Когда-нибудь». В `data.json` это поле `priority` со значением от 1 до 5. Список сортируется по нему, подаренное уходит в конец.

## Проверка ссылок и цен

Каждый день в 18:52 по Москве запланированная задача Claude открывает ссылки и записывает результат в каждый товар. Это та же задача, что проверяет основной вишлист Narlemix: она проходит оба списка подряд. Все магазины она открывает в браузере приложения Claude на компьютере владельца, поэтому в это время компьютер должен быть включён, а приложение Claude открыто. Без компьютера проверятся только магазины, которые отдают страницы облачному запросу (например Яндекс Маркет).

Товары открываются пачками по 5, со страницы берётся только название и блок цен. Проверка занимает примерно 7–8 секунд на товар, на 100 товаров — около 20–25 минут. Каждые 25 товаров результат сохраняется отдельным коммитом, так что сайт обновляется по ходу.

Если магазин показывает капчу (бывает у AliExpress), товар получает пометку «не удалось проверить» с причиной. Капчу нужно один раз пройти в браузере приложения Claude, он запоминает сессию.

- `check` — доступность: `ok` — товар доступен, `gone` — ссылка не работает или товара нет в наличии, `unknown` — проверить не удалось;
- `title` — если название пустое, проверка берёт его со страницы товара;
- `price` — текущая цена с маркетплейса, `priceAt` — когда её считали;
- `pricePrev` и `priceChangedAt` — прошлая цена и дата изменения. На сайте изменение за последние 30 дней видно как «↓ 300 ₽» или «↑ 300 ₽». Самое первое считывание цены изменением не считается.
